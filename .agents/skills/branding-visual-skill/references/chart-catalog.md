# Каталог графиков данных

Контракт: `presentation-chart-spec/1.0` ([JSON Schema](chart-spec.schema.json)). Один график — один файл `source/charts/NN-<имя>.chart.json`, данные — CSV в `source/data/`. Тип графика выбирается в Blueprint (`visualizationMap[].chartType`); здесь — правила кодирования, запреты и способ отрисовки.

Выбор начинается не с типа графика, а с вопроса: **какое отношение в данных доказывает тезис слайда?**

## 1. Выбор по смысловому отношению

| Отношение в тезисе | Пример тезиса | Вместо | Форма | `type` |
|---|---|---|---|---|
| Рейтинг, сравнение категорий | «Telegram дал 38% заявок» | Несортированные столбцы | Отсортированные полосы с одним выделением | `ranked-bar` |
| Из чего сложилось изменение | «Рост дали бренд-съёмки и портреты» | Два столбца «было/стало» | Waterfall (мост) | `waterfall` |
| Отклонение от плана или нормы | «Апрель — единственный провал больше 10%» | Две линии план/факт | Расходящиеся столбцы отклонения | `variance` |
| Изменение между двумя точками у многих объектов | «Чек бренд-съёмки вырос быстрее остальных» | Сгруппированные столбцы | Slope chart | `slope` |
| Разрыв «до / после» по категориям | «Подтверждение ускорилось в 3,6–4,3 раза» | Сгруппированные столбцы | Dumbbell (гантели) | `dumbbell` |
| Динамика нескольких рядов | «Растёт только Telegram» | Одна перегруженная линейная | Small multiples с общей шкалой | `small-multiples` |
| Факт против цели | «Конверсия ниже цели, остальное в норме» | Спидометр | Bullet chart | `bullet` |
| Одна метрика и её тренд | «Июнь — рекорд полугодия» | Крупное число без контекста | KPI + sparkline | `kpi-sparkline` |

Если ни одно отношение не подходит, график не нужен: используй число, таблицу или текст по карте визуальных решений Blueprint.

## 2. Кодирование (`encoding`) и запреты

Значения `encoding` — имена колонок CSV, если не сказано иное. Лимиты проверяет `validate_chart_spec.py`.

| `type` | Обязательные ключи | Необязательные | Лимит | Нельзя |
|---|---|---|---|---|
| `ranked-bar` | `category`, `value` | `aggregate: "sum"` для длинного формата | 12 категорий | Шкала не от нуля; отрицательные значения; хвост больше 12 — сверни в «Прочее» |
| `waterfall` | `step`, `kind` (`start`, `delta`…, `end`), `value` | — | 8 шагов | Сумма шагов не сходится с итогом (валидатор блокирует) |
| `variance` | `category`, `plan`, `actual` | `threshold` (число, % отклонения) | — | Нет базы сравнения в подзаголовке; план равен нулю |
| `slope` | `category`, `from`, `to` | `fromLabel`, `toLabel` | 6 линий | Точки разных периодов или единиц |
| `dumbbell` | `category`, `from`, `to` | `fromLabel`, `toLabel`, `better: "lower" \| "higher"` | 10 строк | Не указано, какое направление лучше |
| `small-multiples` | `x`, `series`, `value` | — | 9 панелей | Разные шкалы без пометки; разное число точек в панелях |
| `bullet` | `metric`, `actual`, `target`, `poor`, `ok`, `max` | `unit` (колонка) | 5 метрик | Цель не утверждена владельцем — тогда `dataStatus: modelled` |
| `kpi-sparkline` | `metric`, `x`, `value` | `unit` (колонка), `derived` | 4 плитки | Sparkline без подписи периода и последнего значения |

Общие запреты: 3D; круговая диаграмма; две оси Y; легенда там, где возможна прямая подпись; цвет как единственный носитель смысла.

### Производные метрики

Метрику, которая получается делением двух других (средний чек = выручка ÷ съёмки, конверсия = сделки ÷ заявки), не вводи в CSV готовыми числами. Объяви её в `encoding.derived`:

```json
"derived": [{"name": "Средний чек", "numerator": "Выручка", "denominator": "Съёмки", "unit": "тыс. ₽", "decimals": 1}]
```

Рендерер считает её из исходных значений. Деление уже округлённых чисел искажает изменение: в демо это дало −0,5% вместо −0,8%.

## 3. Тексты на слайде

1. `title` — вывод с числом, а не тема: «Чек бренд-съёмки вырос на 37%», а не «Средний чек по типам».
2. `subtitle` — что измерено, единицы, период и база: «Средний чек, тыс. ₽, 2024 → 2025».
3. `highlight` — только то, что доказывает заголовок; остальное — контекстный цвет.
4. Прямые подписи вместо легенды.
5. `annotation` — одно предложение «и что?» рядом с графиком.
6. Под графиком — источник и статус данных. Для `modelled` и `synthetic` обязателен `sourceNote`, на слайде появляется метка «МОДЕЛЬ» или «ДЕМО-ДАННЫЕ».
7. Проверка «только заголовки»: заголовки слайдов подряд должны читаться как история.

### Сверка чисел с данными

Валидатор извлекает каждое число из `title` и `annotation` и ищет его среди значений, которые можно получить из данных: исходных значений, итогов, долей, разниц, процентных изменений, отношений, промежуточных сумм waterfall и производных метрик. Округление учитывается по числу знаков в тексте, годы (1900–2099) пропускаются.

Если число не выводится из данных, это ошибка. Исправь текст или, если число законно приходит не из данных (порог, внешний факт), добавь его в `verifiedNumbers` с пояснением:

```json
"verifiedNumbers": [{"value": "30%", "note": "Порог сравнения в тексте, а не значение из данных"}]
```

Проверка ловит опечатки, устаревшие числа и арифметику по округлённым значениям. Смысл фразы она не проверяет: «рост составил бы 0,5 млн» и «спад составил бы 0,5 млн» для неё одинаковы. Поэтому каждую аннотацию ещё раз читают глазами в Data QA.

## 4. Способ отрисовки по форматам

| `type` | PPTX (редактируемо) | HTML | PDF |
|---|---|---|---|
| `ranked-bar` | нативный bar, цвет по точкам | SVG по той же спецификации | рендер PPTX |
| `waterfall` | нативный stacked column с невидимой базой | SVG | рендер PPTX |
| `variance` | нативный column, цвет по знаку, линия порога | SVG | рендер PPTX |
| `slope` | нативный line, подписи вычисляются | SVG | рендер PPTX |
| `small-multiples` | сетка нативных line с общей шкалой | SVG | рендер PPTX |
| `dumbbell` | векторные фигуры из данных | SVG | рендер PPTX |
| `bullet` | векторные фигуры из данных | SVG | рендер PPTX |
| `kpi-sparkline` | текст + нативный мини-line | SVG | рендер PPTX |

«Нативный» — объект диаграммы PowerPoint: данные редактируются через «Изменить данные». «Векторные фигуры» — редактируемые линии и круги без связи с таблицей: при смене данных слайд пересобирается из chart-spec.

Рендерер `scripts/chart-renderer` сейчас выводит только PPTX. Для HTML-сборки рисуй SVG по той же спецификации и тем же токенам `dataviz`, затем прогоняй тот же валидатор; HTML-рендерер — следующий шаг развития.

## 5. Цветовые роли

Берутся из раздела `dataviz` в `tokens.json` Visual DNA:

| Роль | Назначение |
|---|---|
| `focus` | то, что доказывает заголовок |
| `focus-soft` | второстепенный положительный вклад |
| `context`, `context-strong` | остальные категории и ряды |
| `negative`, `negative-soft` | падение, отставание, ниже цели |
| `grid`, `axis` | сетка и оси |
| `band-poor`, `band-ok`, `band-good` | зоны bullet chart (необязательны) |
