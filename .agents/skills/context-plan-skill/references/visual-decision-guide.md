# Карта визуальных решений

- **Короткий текст** — одно утверждение, которое важно услышать дословно.
- **Число** — одна метрика с базой сравнения, периодом и источником.
- **Таблица** — точное сравнение объектов по общим критериям.
- **Диаграмма** — количественная зависимость, динамика или распределение.
- **Схема** — устройство системы и связи между частями.
- **Таймлайн** — изменение во времени, этапы или причинная последовательность.
- **До / после** — конкретное изменение состояния при сопоставимых условиях.
- **Матрица** — выбор между вариантами по двум критериям.
- **Демонстрация** — поведение продукта или процесса, которое важно увидеть в действии.
- **Скриншот с аннотацией** — конкретная деталь интерфейса или доказательство.
- **Визуальная метафора** — абстрактная связь, которую нельзя честно показать данными; метафора не должна подменять доказательство.
- **Фотография или иллюстрация** — эмоциональная или предметная конкретизация, а не заполнение пустоты.

Для каждого выбора ответь: «Что зритель поймёт быстрее благодаря этой форме?» Если ясного ответа нет, оставь простой текст.

## Если форма — диаграмма данных

Не пиши в `form` просто «диаграмма». Определи, какое отношение в данных доказывает тезис, и укажи `chartType`:

| Отношение в тезисе | Пример тезиса | `chartType` |
|---|---|---|
| Рейтинг, сравнение категорий | «Telegram дал 38% заявок» | `ranked-bar` |
| Из чего сложилось изменение | «Рост дали бренд-съёмки и портреты» | `waterfall` |
| Отклонение от плана или нормы | «Апрель — единственный провал больше 10%» | `variance` |
| Изменение между двумя точками у многих объектов | «Чек бренд-съёмки вырос быстрее остальных» | `slope` |
| Разрыв «до / после» по категориям | «Подтверждение ускорилось в 3,6–4,3 раза» | `dumbbell` |
| Динамика нескольких рядов | «Растёт только Telegram» | `small-multiples` |
| Факт против цели | «Конверсия ниже цели, остальное в норме» | `bullet` |
| Одна метрика и её тренд | «Июнь — рекорд полугодия» | `kpi-sparkline` |

Если ни одна строка не подходит, графику, скорее всего, не место на слайде: одно число, таблица или текст объяснят лучше.

Для каждого `chartType` укажи `datasetIds` — таблицы из реестра `datasets`. До утверждения Blueprint у такой таблицы должен быть существующий файл и SHA-256; таблица со статусом `pending` блокирует `approved`.

Сформулируй `mainPoint` экрана как будущий заголовок графика: вывод с числом, которое можно посчитать из данных («Конверсия 34% при цели 40%»), а не тему («Конверсия по месяцам»). Подробные правила кодирования, лимиты и запреты для каждого типа — в каталоге графиков `branding-visual-skill/references/chart-catalog.md`.

## Проверка честности и доступности

- Не используй диаграмму без единиц измерения, периода, базы сравнения и источника.
- Для столбцов начинай количественную шкалу с нуля, если обрезка не объяснена и не оправдана.
- Не используй площадь или объём фигур для сравнения одномерных величин.
- Не полагайся только на цвет: добавь подписи, форму, паттерн или прямую аннотацию.
- Сохраняй различимость категорий при нарушениях цветового зрения и в чёрно-белой печати.
- Для сложной схемы укажи порядок чтения и выдели один главный маршрут.
- Для motion и интерактива опиши статическую замену в PPTX/PDF.
- Если данных недостаточно для честной диаграммы, используй текст, таблицу или явно помеченную гипотезу.
