# Visual DNA package contract

Стабильный идентификатор контракта: `presentation-visual-dna/1.2`. Он не зависит от имени скилла, который создаёт пакет. Пакеты `1.1` считаются legacy и принимаются валидатором с предупреждением.

## visual-dna-manifest.json

Обязательные поля:

- `artifactType: visual-dna`;
- `contract: presentation-visual-dna/1.2`;
- `schemaVersion: 1.2`;
- `status: draft | review | approved`;
- `createdAt`, `owner`, `targetFormats`;
- `sourceBrief` с location, contract, schemaVersion, status и SHA-256;
- `openIssues`, `examples`, `approval`.

Статус `approved` требует утверждённый Style Brief, совпадающий SHA-256, минимум три существующих утверждённых примера с provenance и allowedUsage, отсутствие `openIssues` и заполненный `approval`. Пакет без этого остаётся `draft` или `review`.

## README.md

Название, версия, дата, владелец, область применения, быстрый старт, целевые форматы, ограничения и changelog. Укажи стабильный контракт `presentation-visual-dna/1.2`.

## principles.md

Style Sentence, принципы, эмоциональный диапазон, постоянные и переменные признаки.

## tokens.css / tokens.json

Одинаковые роли цветов, шрифтов, размеров, расстояний и форм. JSON — переносимый источник; CSS — готовое применение в web. Используй роли из `tokens.schema.json` и CSS-переменные `--color-*`, `--font-*`, `--space-*`, `--radius-*`, `--border-width-*`, `--shadow-*`.

Необязательный раздел `dataviz` описывает роли графиков данных: цвета `focus`, `focus-soft`, `context`, `context-strong`, `negative`, `negative-soft`, `grid`, `axis` (и при необходимости `band-*`), размеры в pt, толщины линий и формат чисел. Его цвета дублируются в CSS как `--dataviz-*`. Раздел нужен рендереру графиков `branding-visual-skill`; без него пакет валиден, но графики придётся собирать через `dna-adapter.json`.

Сюжеты, ракурсы, свет, фактура, обработка, иллюстрации, иконки и запреты.

## motion.md

Назначение движения, длительности, easing, последовательность, reduced-motion и статические замены.

## do-dont.md

Конкретные пары правильного и ошибочного применения. Не повторяй абстрактные прилагательные.

## prompts.md

Промпты для создания новых материалов. Они должны ссылаться на токены и принципы пакета, содержать задачу, композицию и запреты, а не только название эстетики.

## references-manifest.md

Для каждого источника: URL/путь, владелец, дата доступа, что извлечено, статус лицензии, можно ли включать в публичную выдачу.

## examples/

Только утверждённые визуальные файлы либо точные задания со статусом pending. У каждого примера есть provenance и назначение.
